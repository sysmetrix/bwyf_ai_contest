## 2. 설치·실행 절차

**Windows 가장 쉬운 방법**: 압축을 푼 뒤 `설치.bat`을 더블클릭하면 설치부터 실행까지 한 번에 됩니다. 다음부터는 `실행.bat`만 더블클릭하면 되고, 브라우저가 자동으로 열립니다. 문제가 생기면 창이 닫히지 않고 이유를 보여 줍니다.

처음부터 순서대로 따라 하면 됩니다.

```bash
# 1) 프로젝트 폴더로 이동
cd seomu-biseo

# 2) 필요한 패키지 설치
pip install -r requirements.txt

# 3) 실행
python run.py
```

실행 후 터미널에 다음과 같이 뜨면 정상입니다.

```
서비가 시작됐습니다 → http://localhost:8000
(끝내려면 Ctrl+C)
```

브라우저에서 **http://localhost:8000** 을 엽니다. 포트를 바꾸고 싶으면 `python run.py --port 8010` 처럼 실행합니다. 설치 직후에는 AI 연결 없이(규칙 기반) 모든 기능이 바로 동작합니다.

### 테스트 실행 (선택)

```bash
pip install pytest
python -m pytest -q
```

핵심 기능 19개 테스트(업무 분류 정확도, 기한 계산, 전결권자 판정, 서식 생성(.docx/.hwpx 둘 다), 기관 등록·삭제, 메일 연결 설정, AI 연결 추가·삭제, 원본 보호, AI 연결 실패 폴백 등)가 모두 통과하는 것을 확인할 수 있습니다.

## 3. LLM 연결 설정

서비 본체는 **어떤 모델이 연결됐는지 모르는 구조**입니다(`app/llm.py`가 유일한 연결부). 모델을 바꿔도 기한 계산·전결권자 판정 같은 핵심 결과는 흔들리지 않습니다.

| 역할 | 하는 일 | 모델 없을 때 |
|---|---|---|
| 업무 분류·정보 추출 | 말을 보고 업무 종류 판단 | 키워드 규칙으로 동작 |
| 안내 문장 작성 | 근거 조문 기반 요약 | 정해진 문장 템플릿 사용 |
| 프로필 초안 보완 | 규정에서 값 추출 | 정규식 추출 규칙만 사용 |

**연결 방법 (화면 "AI 모델 연결")**

1. OpenAI 호환 API라면 어떤 모델이든 연결 가능합니다. 기본 제공 연결은 `ollama`·`vllm`·`gov_ai` 3개이며, **"새 연결 추가"로 이름·주소·키 환경변수만 적으면 몇 개든 추가**할 수 있습니다(예: OpenAI, 기관 AI 공통기반 등). 더 이상 안 쓰는 연결은 옆의 ✕ 버튼으로 삭제할 수 있고, 삭제된 연결을 쓰던 역할은 자동으로 "연결 안 함"으로 전환되어 서비스가 끊기지 않습니다.
2. 역할마다 다른 연결을 고를 수 있습니다. 모델 이름을 적고 **저장 → 연결 테스트**를 누르면 연결 여부를 바로 확인합니다.
3. API 키는 화면이나 `config.yaml`에 직접 적지 않고, **환경변수 이름만** 적습니다. 실제 키 값은 서버를 실행하는 환경에 미리 설정해 둡니다.

**공통기반 지원 모델 구동 방법 (이식성 입증)**

행정안전부 AI 공통기반에서 지원하는 모델(Gemma, EXAONE 등)은 Ollama로 로컬에 받아 연결하면 됩니다.

```bash
# https://ollama.com 에서 Ollama 설치 후
ollama pull gemma3:4b          # 업무 분류용(가벼운 모델)
ollama pull exaone3.5:7.8b     # 안내 문장·프로필 보완용
```

화면에서 역할마다 `ollama`를 고르고 모델 이름(`gemma3:4b`, `exaone3.5:7.8b`)을 입력 후 저장·연결 테스트하면 됩니다. **"모델 비교 테스트"**에서 서로 다른 모델(2종 이상)을 추가해 같은 질문 세트로 돌리면 업무 분류 정확도·응답 속도를 한 표로 비교할 수 있습니다 — 이 결과 표가 "모델 비종속" 구조의 증빙 자료입니다.

> 이번 제출 환경에는 Ollama가 설치되어 있지 않아 실제 모델 구동 결과표는 포함하지 못했습니다. 위 절차대로 Ollama 설치 후 역할별 연결·모델 비교 테스트를 실행하면 바로 결과를 확인할 수 있습니다.

## 4. 모의데이터 안내

| 파일/폴더 | 용도 | 투입 방법 |
|---|---|---|
| `data/orgs/demo-agency/` | 가상 출연기관 프로필·규정·서식 | 기본 포함, 별도 투입 불필요 |
| `data/orgs/demo-city/` | 가상 지자체 프로필·규정·서식 | 기본 포함, 별도 투입 불필요 |
| `data/common/rules/*.md` | 공통 규정(출장·물품·복무·행사·기안) | 기본 포함 |
| `data/common/tasks.yaml` | 업무 정의(7종) | 기본 포함, 새 업무 추가 시 이 파일에 항목만 더하면 모든 기관에 적용됨 |
| `data/common/eval_set.yaml` | 모델 비교 테스트용 질문 세트(18문항) | 기본 포함 |

포함된 규정·프로필·서식은 전부 **시연용 가상 데이터**이며, 기관명도 "가상 ○○출연기관"처럼 완전히 가상화되어 있습니다.

**새 기관(실제 기관) 적용 시**: "기관 프로필 → 새 기관 등록"에서 기관을 만들고, "규정 폴더 가져오기"에 실제 규정 파일이 있는 폴더 경로를 입력하면 됩니다. 원본 폴더는 읽기 전용으로만 접근하고, 복사본만 `data/orgs/<기관>/rules/imported/`에 저장됩니다. 더 이상 쓰지 않는 기관은 "기관 프로필" 화면에서 삭제할 수 있으며, 실수로 지워도 영구 삭제가 아니라 `data/orgs_deleted/`에 보관되어 복구할 수 있습니다.

## 5. 기능 사용 순서 (핵심 흐름)

**흐름 1 — 상황을 말하면 절차·서식까지 안내**
1. 좌측에서 기관·담당자를 선택합니다 (담당자는 "+"로 새로 등록 가능).
2. 입력창에 "11월 3일부터 4일까지 세종 출장 다녀와서 정산해야 해요"처럼 상황을 말합니다 (마이크 버튼으로 음성 입력도 가능).
3. 업무 분류 → 처리 절차 → 기한(날짜 자동 계산) → 전결권자 → 근거 조문 → 서식 초안까지 한 번에 안내됩니다.

**흐름 2 — 내 할 일 관리 + 메일 알림**
1. 담당자를 선택하면 상단에 "OOO님, 기한 지난 건 N · 임박 N · 최근 7일 처리 N건" 브리핑이 뜹니다.
2. 좌측 "내 할 일"에서 기한이 있는 처리 건을 확인하고 완료 처리할 수 있습니다.
3. 답변 카드의 "이 안내 메일로 받기"를 누르면 담당자 본인 메일로 요약을 보냅니다(발신 전용 — 받은 메일은 읽지 않음). "설정" 화면에서 SMTP 연결(주소·계정 환경변수)을 먼저 등록해야 하며, 비밀번호는 화면에 입력하지 않고 서버 실행 환경의 환경변수로만 전달됩니다.

**흐름 3 — 서식 보관함**
1. "서식 보관함"에서 업무별로 연결된 서식(.docx 또는 .hwpx)을 확인하고 원본을 내려받습니다.
2. "서식 바꾸기"로 기관이 실제로 쓰는 서식을 올리면(서식 안에 `{{항목}}`처럼 자리표시 필요), 다음부터 그 서식으로 초안이 채워집니다. **.hwpx도 .docx와 동일하게 자동 채우기를 지원**합니다.
3. "서비에게 초안 요청"을 누르면 서비 화면으로 이동해 해당 업무의 예시 질문을 자동으로 물어보고 초안까지 만들어 줍니다.

**흐름 4 — 기관 설정·비교**
1. "기관 프로필"에서 규정 폴더를 가져와 AI 초안을 만들고 확인 후 저장합니다. 관행 메모가 규정과 충돌하면 경고가 뜹니다.
2. 왼쪽 위에서 기관을 바꿔 같은 질문을 하면, 기관 규정에 따라 기한·전결권자가 달라지는 것을 볼 수 있습니다.
3. "설정"에서 담당자 개인 정보, 메일 알림 연결을 한곳에서 관리합니다.

## 6. 알려진 제약 사항

- AI 모델을 연결하지 않아도(기본 상태) 모든 핵심 기능이 규칙 기반으로 동작합니다. 모델은 안내 문장을 다듬고 분류 정확도를 보조하는 역할입니다.
- 근거 조문 검색은 키워드 기반 간이 검색이라, 아주 드물게 관련성이 낮은 조문이 함께 표시될 수 있습니다(예: "신청" 같은 공통 단어가 겹치는 경우).
- 메일 발신(SMTP)은 실제 메일 계정·환경변수가 설정된 환경에서만 동작합니다. 기본 상태는 "연결 안 함"이며, 이 경우 메일 버튼을 눌러도 발신하지 않고 안내만 표시합니다.
- 서식 자동 채우기는 `{{항목}}` 자리표시가 있는 **.docx, .hwpx** 두 형식만 지원합니다. 그 외 형식이나 구형 `.hwp`는 자동 채우기 없이 원본 다운로드만 가능하며, `.hwp`는 한글에서 HWPX나 PDF로 저장해 올려야 합니다.
- 음성 입력은 브라우저 내장 음성 인식(Web Speech API)을 사용하므로 크로미움 계열 브라우저에서만 동작하며, 마이크 권한을 허용해야 합니다. 음성 출력(TTS)은 제공하지 않습니다.

### 재배포 제한이 있는 오픈소스·외부 라이브러리

| 패키지 | 용도 | 라이선스 |
|---|---|---|
| FastAPI, uvicorn, httpx, PyYAML, python-docx, pypdf, python-multipart | 서버·문서 처리 | 모두 MIT/Apache-2.0 계열, 재배포 제한 없음 |

별도의 재배포 제한 라이브러리는 사용하지 않았습니다.

## 7. 개발 경위 요약

**문제 인식**: 출장·물품·행사·복무·결재 등 서무 업무는 종류마다 절차·서식·규정·기한이 제각각인데, 매뉴얼은 문서로만 있어 찾아 읽기 어렵고 실제 처리 순서는 전임자에게 구두로 배우는 것이 현실입니다. 서무 담당은 자주 바뀌고 대부분 겸임이라 같은 시행착오와 반려가 반복됩니다.

**접근 방식**: "규정을 모델에 학습(파인튜닝)시키는" 대신, 공통 규정·기관 규정·부서 보충을 3층으로 나눠 저장해 두고 **질문이 들어올 때마다 관련 조문을 검색해 근거와 함께 보여주는** 구조를 택했습니다. 이렇게 하면 (1) 모델을 바꿔도 안내 내용이 흔들리지 않고, (2) 규정이 개정되면 파일만 바꾸면 즉시 반영되며, (3) "제12조에 따라"처럼 근거를 정확히 인용할 수 있습니다. 기한 계산·전결권자 판정처럼 틀리면 안 되는 부분은 AI가 아니라 규칙(코드)으로 고정해, 모델 유무와 무관하게 항상 같은 결과가 나오도록 설계했습니다.

이후 담당자 개인별 등록·할 일 관리·메일 알림·음성 입력을 추가해 "규정 안내 도구"에서 "개인이 매일 쓰는 비서"로 범위를 넓혔고, AI 연결도 고정된 몇 개가 아니라 원하는 만큼 추가·삭제할 수 있도록 바꿔 타 기관·타 모델로의 이식성을 높였습니다. 서식도 .docx뿐 아니라 공공기관에서 실제로 많이 쓰는 **.hwpx 자동 채우기**까지 지원해, 실제 현장 적용 시 서식 형식 때문에 막히는 일이 없도록 했습니다.
