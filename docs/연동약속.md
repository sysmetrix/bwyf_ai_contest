# 파트 사이의 약속 (초안)

각자 AI로 따로 만들어도 마지막에 맞물리도록, 두 파트가 함께 쓰는 형식을 여기에 정합니다.
**이 문서를 바꾸면 관련된 담당자 모두에게 알려야 합니다.**

```
 data/ (지은) ──규정·서식 파일──▶ app/ 서무비서 (영운) ◀──결재 연동 API──▶ intranet/ 가상 인트라넷 (준호)
```

---

## 1. 지은 → 영운: 규정·서식 파일 형식

- 규정·지침·매뉴얼은 Markdown(`.md`) 파일로 `data/` 아래에 둡니다.
- (정할 것) 파일 맨 위 메타데이터 항목. 제안: `---` 사이에 YAML로 문서코드, 종류(규정·지침·매뉴얼·서식), 제정·개정일, 관련 업무, 관련 서식
- (정할 것) 조문 표기. 제안: `**제○조(제목)**`, 개정 표시는 `<개정 yyyy. m. d.>`
- (정할 것) 서식 파일 형식(`.md`, `.docx`, `.hwpx` 중 무엇)과 폴더 구조
- 형식이 정해지면 지은이 `data/README.md`에 적고, 이 장은 그 파일을 가리킵니다.
- 서무비서가 읽는 메타데이터 항목의 **이름을 바꾸거나 빼면** 영운에게 먼저 알려 주세요.

## 2. 지은 → 영운: 업무별 단계 (진행 바·체크리스트)

- (정할 것) 업무별 "단계 → 할 일 → 기한 → 서식 → 결재 → 근거 조문"을 어디에 정리할지 (예: `data/조문지도.md`)
- 화면의 단계 이름과 체크리스트 항목은 지은이 정리한 단계·할 일과 같은 이름을 씁니다. 지은은 단계 이름을 바꿀 때 영운에게 알려 줍니다.
- 예시 형태 (확정 전, 영운은 이 예시 데이터로 화면을 먼저 만들 수 있습니다):
  ```json
  {
    "task": "출장·여비",
    "steps": [
      {"name": "출장 신청", "todo": ["출장신청서 작성", "결재 상신"], "due": "출장 전", "form": "F02", "done": true},
      {"name": "출장 복명", "todo": ["복명서 작성"], "due": "복귀 후", "form": "F03", "done": false}
    ]
  }
  ```

## 3. 영운 ↔ 준호: 결재 연동 API

- 인트라넷 API(주소·요청·응답 형식)는 준호가 관리하고, 규격 원본은 `intranet/README.md`의 "연동 API" 표에 둡니다.
- 서무비서 쪽 연결부는 영운이 만듭니다. API를 바꿀 때는 준호와 영운이 먼저 맞춥니다.
- (정할 것) 포트. 제안: 서무비서 8000, 인트라넷 8100
- (정할 것) 최소 API 목록. 제안: 로그인(가상 사용자), 기안 상신, 결재함 목록, 결재 상태 조회, 첨부 업로드
- (정할 것) 결재선 역할 이름. 서무비서와 인트라넷이 같은 이름을 쓰고, 가상 사용자 목록은 지은이 만드는 가상 기관 설정과 맞춥니다.

## 4. 가상 기관 기준값 (지은 → 모두)

- (정할 것) 가상 기관명·지역명, 부서와 직위 체계, 가상 사용자 목록
- 정해지면 지은이 기준 문서(예: `data/기관설정서.md`)에 적고, 영운·준호는 그 값을 그대로 씁니다.
