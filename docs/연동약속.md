# 파트 사이의 약속 (초안 v0.1)

각자 AI로 따로 만들어도 마지막에 맞물리도록, 두 파트가 함께 쓰는 형식을 여기에 정합니다.
**이 문서를 바꾸면 관련된 담당자 모두에게 알려야 합니다.**

- 상태: 초안. 각 장의 "확인할 사람"이 동의하면 `(초안)` 표시를 지웁니다.
- 기준 데이터: 지은의 `data/` (기관설정서 v0.5, 조문지도 v0.1)

```
 data/ (지은) ──파일 읽기──▶ app/ 서무비서 (영운, 포트 8000) ◀──HTTP API──▶ intranet/ 가상 인트라넷 (준호, 포트 8100)
```

---

## 0. 공통 (초안, 확인할 사람: 영운·준호)

| 항목 | 약속 |
|---|---|
| 서무비서 주소 | http://localhost:8000 |
| 가상 인트라넷 주소 | http://localhost:8100 |
| 인트라넷 주소 설정 | 서무비서는 환경변수 `INTRANET_URL`로 읽고, 없으면 `http://localhost:8100`을 씁니다 |
| 데이터 폴더 위치 | 서무비서는 레포 루트의 `data/`를 읽습니다. 경로를 코드에 박지 말고 설정값 하나로 둡니다 |
| 문자 인코딩 | 모든 파일과 API는 UTF-8 |
| 날짜·시간 | API는 `2026-11-05`, `2026-11-05T14:30:00` 형식. 화면에 보일 때는 `2026. 11. 5.` |
| 금액 | API는 원 단위 정수(`3000000`). 화면에 보일 때는 `300만원` 또는 `3,000,000원` |

## 1. 지은 → 영운: 규정·서식 파일 형식 (초안, 확인할 사람: 지은·영운)

형식 원본은 `data/README.md`입니다. 서무비서가 기대는 부분만 여기에 고정합니다.

### 1-1. 파일 머리 메타데이터 (YAML)

모든 `.md` 파일 맨 위 `---` 사이에 있습니다. 서무비서는 아래 항목을 읽습니다.

| 항목 | 예 | 있는 곳 |
|---|---|---|
| `문서코드` | `여비`, `M2`, `C1` | 규정·지침·매뉴얼·공통 |
| `서식코드` | `F02` | 서식 |
| `문서명` / `서식명` | `여비 규정` / `출장신청서` | 모두 |
| `층` | `공통`, `기관`, `부서·시설` | 규정·지침·매뉴얼·공통 |
| `종류` | `규정`, `업무매뉴얼`, `상위 법령 (대통령령)` | 규정·지침·매뉴얼·공통 |
| `제정`, `개정`, `기준일` | `2015-11-03`, `[2018-01-01, 2023-12-18]` | 규정 |
| `관련업무` | `[출장·여비]` | 모두 |
| `관련문서`, `관련서식` | `[여비, C1]`, `[F02, F03]` | 매뉴얼 |
| `근거`, `작성시점` | `[취업 규정 제22조①]`, `출장 전` | 서식 |

**규칙**: 지은은 위 항목의 **이름을 바꾸거나 빼기 전에** 영운에게 먼저 알립니다. 새 항목을 더하는 것은 알리지 않아도 됩니다.

### 1-2. 본문 표기

- 조문: `**제○조(제목)**`, 개정 표시: `<개정 yyyy. m. d.>`
- 설정값은 기관설정서 8장의 **설정값 ID**(`APV-01`, `TRV-05` 등)로 부릅니다. 서무비서가 숫자를 안내할 때는 ID와 출처를 함께 보여 줍니다.

### 1-3. 업무 이름 (두 파트가 같은 글자를 씀)

`관련업무` 값과 서무비서 화면의 업무 이름은 아래 7개를 **글자 그대로** 씁니다.

| 업무 | 매뉴얼 | 상태 |
|---|---|---|
| 기안·결재 | M1 | 작성 완료 |
| 출장·여비 | M2 | 작성 완료 |
| 복무 | M3 | 작성 완료 |
| 구매·지출 | M4 | 작성 완료 |
| 행사 운영 | M5 | 예정 |
| 외부강의 신고 | M6 | 예정 |
| 전문가 활용비 | M7 | 예정 |

여러 업무에 걸친 문서는 `모든 업무`를 씁니다.

## 2. 지은 → 영운: 업무별 단계 (진행 바·체크리스트) (초안, 확인할 사람: 지은·영운)

- 원본은 `data/01_조문지도.md` 2장 표입니다. 열 순서: **단계 | 할 일 | 기한·기준 | 서식 | 결재·협조 | 근거 | 종류**
- 화면의 진행 바 단계 이름과 체크리스트 항목은 조문지도의 "할 일"을 그대로 씁니다. 지은은 이 표의 열 이름이나 단계 이름을 바꿀 때 영운에게 알립니다.
- 서무비서 안에서 화면으로 넘길 때는 아래 형태로 바꿔 씁니다. (영운이 서버를 만들기 전에는 이 예시로 화면을 먼저 만들 수 있습니다)

```json
{
  "task": "출장·여비",
  "steps": [
    {"no": "2", "name": "출장 신청", "due": "사전 신청", "forms": ["F02"],
     "approval": "직원 → 실장·관장·센터장 전결", "basis": ["취업§22①", "세칙별표 1", "M2"],
     "basis_type": ["규정", "매뉴얼"], "done": true},
    {"no": "4", "name": "결과 보고", "due": "관외는 출장복명서 필수", "forms": ["F03"],
     "approval": "출장 결재선과 같음", "basis": ["취업§22③", "지급 2-④", "M2"],
     "basis_type": ["규정", "매뉴얼"], "done": false}
  ]
}
```

- `basis_type`이 `권장`이면 화면에 "규정이 아니라 재단 권장 기준"이라고 표시합니다 (기관설정서 8장 행사 운영 주석).

## 3. 영운 ↔ 준호: 결재 연동 API (초안, 확인할 사람: 준호·영운)

- 인트라넷 API는 준호가 관리합니다. 확정되면 규격 원본은 `intranet/README.md`의 "연동 API" 표로 옮기고, 이 장은 그 표를 가리킵니다.
- 서무비서 쪽 연결부는 영운이 만들고, **한 파일(모듈)** 에 모읍니다. 인트라넷 주소나 응답이 바뀌면 그 파일만 고치면 되게 합니다.
- 주소와 응답 형식을 바꿀 때는 준호와 영운이 먼저 맞춥니다.

### 3-1. 최소 API 목록 (제안)

모든 요청·응답은 JSON입니다. 로그인은 시연용이라 `user_id`만 넘깁니다 (비밀번호 없음).

| 기능 | 방법·주소 | 보내는 것 | 받는 것 |
|---|---|---|---|
| 살아 있는지 확인 | `GET /api/health` | — | `{"ok": true}` |
| 가상 사용자 목록 | `GET /api/users` | — | 사용자 배열 (3-3 형식) |
| 기안 상신 | `POST /api/approvals` | 3-2 형식 | `{"id": "A-0001", "status": "submitted", "doc_no": "산울림-0001"}` |
| 결재함 목록 | `GET /api/approvals?user_id=u01&box=todo` | `box`: `todo`(내가 결재할 것), `mine`(내가 올린 것), `done`(끝난 것) | 결재 문서 요약 배열 |
| 결재 문서 보기 | `GET /api/approvals/{id}` | — | 결재 문서 전체 + 결재선별 처리 상태 |
| 결재 처리 | `POST /api/approvals/{id}/actions` | `{"user_id": "u04", "action": "approve", "comment": ""}` | 바뀐 결재 문서 |
| 첨부 올리기 | `POST /api/files` (multipart) | 파일 | `{"file_id": "F-0001"}` |

오류는 HTTP 상태 코드와 함께 `{"error": {"code": "NOT_FOUND", "message": "쉬운 한국어 설명"}}`로 돌려줍니다.

### 3-2. 기안 상신 형식 (제안)

```json
{
  "title": "물품 구매 품의 (노트북 2대)",
  "task": "구매·지출",
  "form_code": "F09",
  "drafter_id": "u01",
  "line": [
    {"user_id": "u02", "type": "검토"},
    {"user_id": "u05", "type": "협조"},
    {"user_id": "u03", "type": "전결"}
  ],
  "fields": {"금액": 3000000},
  "body": "본문(Markdown)",
  "file_ids": ["F-0001"],
  "source": "서무비서"
}
```

- `task`는 1-3의 업무 이름, `form_code`는 지은의 서식코드를 씁니다.
- `line.type`은 기관설정서 4-1의 결재 용어 **검토, 협조, 결재, 전결, 대결** 중 하나입니다.
- `line`은 순서대로 처리합니다 (기관설정서 4-1: 하위 → 상위, 같은 직급은 소속 부서 → 타부서).

### 3-3. 처리 상태와 동작

| 상태 코드 | 화면 표시 |
|---|---|
| `submitted` | 상신 |
| `in_progress` | 결재 중 |
| `approved` | 결재 완료 |
| `rejected` | 반려 |
| `withdrawn` | 회수 |

| 동작 코드 | 뜻 |
|---|---|
| `approve` | 승인 (검토·결재·전결·대결) |
| `agree` / `disagree` | 협조 동의 / 부동의 (부동의는 `comment`에 사유 필수, 사무§20) |
| `reject` | 반려 |
| `withdraw` | 기안자 회수 |

코드 값은 영어로, 화면 글자는 한국어로 둡니다. 두 파트가 코드 값만 맞추면 화면 글자는 각자 바꿔도 됩니다.

## 4. 시연 사용자와 결재선 (초안, 확인할 사람: 지은·준호·영운)

- 기관명·조직·직위는 `data/00_기관설정서.md`를 그대로 따릅니다. 영운·준호는 값을 따로 만들지 않습니다.
- 사람 이름은 넣지 않고 **소속 + 직위**로만 부릅니다 (기관설정서 9장).
- 인트라넷의 가상 사용자 목록(제안). 기관설정서 9장의 P1~P3에 결재권자를 더했습니다.

| user_id | 소속 | 직위 | 역할 |
|---|---|---|---|
| u01 | 산울림청소년센터 ○○부 | 대리 (4급) | P1 겸임 서무담당, 주 사용자 (기안자) |
| u02 | 산울림청소년센터 ○○부 | 부장 (2급) | 검토 |
| u03 | 산울림청소년센터 | 센터장 (전문계약직 1급) | 부서장 전결 |
| u04 | — | 대표이사 | 최종 결재 |
| u05 | 전략경영실 경영지원부 | 부장 (2급) | 200만원 초과 구매 협조 (APV-02) |
| u06 | 전략경영실 경영지원부 | 직원 | P2 회계·계약 검토 |
| u07 | 전략경영실 전략기획부 | 부장 (2급) | P3 규정·서식 등록 관리자 |

`GET /api/users` 응답 한 줄 예: `{"id": "u01", "dept": "산울림청소년센터 ○○부", "rank": "4급", "position": "대리", "label": "산울림청소년센터 대리"}`
