# 파트 사이의 약속 (v0.2)

각자 AI로 따로 만들어도 마지막에 맞물리도록, 두 파트가 함께 쓰는 형식을 여기에 정합니다.
**이 문서를 바꾸면 관련된 담당자 모두에게 알려야 합니다.**

- 상태: 기준안. 누구나 고칠 수 있지만, 이 문서는 여러 파트가 함께 쓰므로 **관련 담당자가 단톡방에서 OK한 뒤** 머지합니다 (AGENTS.md 2장).
- 기준 데이터: 지은의 `data/` (기관설정서 v0.5, 조문지도 v0.1)
- v0.2 변경: 인트라넷에 서버를 따로 두지 않고, **서무비서 하나만 켜면 인트라넷 화면도 같이 뜨는 방식**으로 바꿈 (2026-11-05 실행 점검 결과 반영)

## 한눈에 보기

```
 data/ (지은) ──규정 읽기──▶ 서무비서 (app/, 영운) · http://localhost:8000
                              ├ 안내·서식 초안 → 결재 패키지 → [가상 결재함]  ◀─┐
                              └ /intranet/ → intranet/index.html (준호)          │
                                              결재함 읽기, 상신·승인·반려 ───────┘
```

- 심사위원은 **서무비서 하나만 켭니다.** 인트라넷은 서무비서 화면의 "인트라넷 열기" 버튼이나 http://localhost:8000/intranet/ 로 엽니다.
- 결재 문서는 **서무비서 안의 가상 결재함** 한 곳에만 저장합니다. 인트라넷 화면은 그 결재함을 보여 주고 버튼 결과를 돌려주는 "창"입니다.
- 준호는 개발 중에 `intranet/index.html`을 더블클릭해서 따로 열어 봐도 됩니다. 이때는 서무비서가 없으니 화면에 들어 있는 견본 데이터를 보여 줍니다 (3-4).

## 0. 공통

| 항목 | 약속 |
|---|---|
| 서무비서 주소 | http://localhost:8000 (포트가 사용 중이면 서무비서가 8001~8009 중 빈 번호로 엽니다) |
| 인트라넷 주소 | 서무비서 주소 뒤에 `/intranet/` (별도 포트 없음) |
| 인트라넷이 서무비서를 부르는 주소 | **앞에 주소를 붙이지 않은 상대 주소** `/api/...` (포트가 바뀌어도 그대로 동작) |
| 데이터 폴더 | 서무비서는 레포 루트의 `data/`를 기관 "재단법인 부천여성청소년재단"의 규정으로 씁니다 (1-4) |
| 문자 인코딩 | 모든 파일과 API는 UTF-8 |
| 날짜·시간 | API는 `2026-11-05`, `2026-11-05T14:30:00`. 화면에는 `2026. 11. 5.` |
| 금액 | API는 원 단위 정수(`3000000`). 화면에는 `300만원` 또는 `3,000,000원` |
| 결재 연결 방식 | 시연·제출본은 `config.yaml`의 `approval.provider: mock`(가상 결재함)만 씁니다. 실제 그룹웨어 연결(`amaranth_10`)은 켜지 않습니다 (AGENTS.md 4장) |

## 1. 지은 → 영운: 규정·서식 파일 형식

형식 원본은 `data/README.md`입니다. 서무비서가 기대는 부분만 여기에 고정합니다.

### 1-1. 파일 머리 메타데이터 (YAML)

모든 `.md` 파일 맨 위 `---` 사이에 있습니다. 서무비서는 아래 항목을 읽습니다.

| 항목 | 예 | 있는 곳 |
|---|---|---|
| `문서코드` | `여비`, `M2`, `C1` | 규정·지침·매뉴얼·공통 |
| `서식코드` | `F02` | 서식 |
| `문서명` / `서식명` | `여비 규정` / `출장신청서` | 모두 |
| `층` | `공통`, `기관`, `부서·시설` | 규정·지침·매뉴얼·공통 |
| `종류` | `규정`, `업무매뉴얼`, `상위 법령 (대통령령)` | 규정·지침·매뉴얼·공통 |
| `제정`, `개정`, `기준일` | `2015-11-03`, `[2018-01-01, 2023-12-18]` | 규정 |
| `관련업무` | `[출장·여비]` | 모두 |
| `관련문서`, `관련서식` | `[여비, C1]`, `[F02, F03]` | 매뉴얼 |
| `근거`, `작성시점` | `[취업 규정 제22조①]`, `출장 전` | 서식 |

**규칙**: 지은은 위 항목의 **이름을 바꾸거나 빼기 전에** 영운에게 먼저 알립니다. 새 항목을 더하는 것은 알리지 않아도 됩니다.

### 1-2. 본문 표기

- 조문: `**제○조(제목)**`, 개정 표시: `<개정 yyyy. m. d.>`
- 설정값은 기관설정서 8장의 **설정값 ID**(`APV-01`, `TRV-05` 등)로 부릅니다. 서무비서가 숫자를 안내할 때는 ID와 출처를 함께 보여 줍니다.

### 1-3. 업무 이름 (두 파트가 같은 글자를 씀)

`관련업무` 값과 서무비서 화면의 업무 이름은 아래 7개를 **글자 그대로** 씁니다.

| 업무 | 매뉴얼 |
|---|---|
| 기안·결재 | M1 |
| 출장·여비 | M2 |
| 복무 | M3 |
| 구매·지출 | M4 |
| 행사 운영 | M5 |
| 외부강의 신고 | M6 |
| 전문가 활용비 | M7 |

여러 업무에 걸친 문서는 `모든 업무`를 씁니다.

### 1-4. 서무비서 기관 프로필에 넣을 값 (영운이 넣고, 값의 원본은 지은)

2026-11-05 점검에서 서무비서는 `data/` 파일 49개를 모두 읽었지만, **아래 값은 규정에서 스스로 찾지 못했습니다.** 그래서 영운이 부천여성청소년재단 기관 프로필(`app/data/orgs/<기관ID>/profile.yaml`)에 직접 넣고, `sources`에 설정값 ID를 적습니다.

| 프로필 항목 | 값 | 설정값 ID | 점검 때 상태 |
|---|---|---|---|
| `org.name` | 재단법인 부천여성청소년재단 | 기관설정서 1장 | — |
| `approval.line` | 담당 → 부장 → 실장·관장·센터장 → 대표이사 | 기관설정서 3·4장 | 견본값(팀장·실장)이 들어감 |
| `approval.thresholds` | 500만원 이하 실장·관장·센터장 전결, 초과 대표이사 | APV-01 | 일부만 찾음 |
| (새 항목) 협조 | 추정금액(부가세 포함) 200만원 초과 → 경영지원부장 협조 + 계약 의뢰 | APV-02, PUR-01 | **빠짐**. 프로필에 항목이 없어 영운이 추가 |
| `purchase.single_quote_limit_won` | 2000000 (200만원 이상이면 2개 업체 이상 비교견적. 시 보조금사업은 100만원) | PUR-02 | **못 찾음** |
| `deadlines.travel_settlement_days` | 14 (출장 마친 다음 날부터 2주 이내) | TRV-05 | **못 찾음** |
| `allowances.daily_won` | 25000 (관외 일비) | TRV-02 | **못 찾음** |
| `deadlines.leave_request_days_before` | (정할 것) 기관설정서에 없음 | — | 지은이 규정에서 확인 |

- **서무비서는 루트 `data/`를 직접 읽습니다.** "규정 폴더 가져오기"로 `app/data/orgs/<기관ID>/rules/imported/`에 복사하는 방식은 개발 중 확인용으로만 쓰고, 그 복사본은 커밋하지 않습니다(루트 `.gitignore`에 등록). 복사본을 올리면 지은이 `data/`를 고쳐도 서무비서에는 옛 내용이 남습니다.
- 서무비서는 시작할 때부터 이 기관이 들어 있게 합니다. 첫 화면에서 견본 기관(demo-agency, demo-city) 대신 이 기관이 맨 위에 보이게 합니다.
- 지은은 8장 값을 바꾸면 영운에게 알립니다. 영운은 프로필을 같은 값으로 고칩니다.

## 2. 지은 → 영운: 업무별 단계 (진행 바·체크리스트)

- 원본은 `data/01_조문지도.md` 2장 표입니다. 열 순서: **단계 | 할 일 | 기한·기준 | 서식 | 결재·협조 | 근거 | 종류**
- 화면의 진행 바 단계 이름과 체크리스트 항목은 조문지도의 "할 일"을 그대로 씁니다. 지은은 이 표의 열 이름이나 단계 이름을 바꿀 때 영운에게 알립니다.
- 서무비서 안에서 화면으로 넘길 때는 아래 형태로 바꿔 씁니다.

```json
{
  "task": "출장·여비",
  "steps": [
    {"no": "2", "name": "출장 신청", "due": "사전 신청", "forms": ["F02"],
     "approval": "직원 → 실장·관장·센터장 전결", "basis": ["취업§22①", "세칙별표 1", "M2"],
     "basis_type": ["규정", "매뉴얼"], "done": true},
    {"no": "4", "name": "결과 보고", "due": "관외는 출장복명서 필수", "forms": ["F03"],
     "approval": "출장 결재선과 같음", "basis": ["취업§22③", "지급 2-④", "M2"],
     "basis_type": ["규정", "매뉴얼"], "done": false}
  ]
}
```

- `basis_type`이 `권장`이면 화면에 "규정이 아니라 재단 권장 기준"이라고 표시합니다 (기관설정서 8장 행사 운영 주석).

## 3. 영운 ↔ 준호: 결재 연동 (서무비서의 가상 결재함)

### 3-1. 흐름

| # | 어디서 | 무엇을 | 결재함 상태 |
|---|---|---|---|
| 1 | 서무비서 | 사용자가 안내를 받고 "결재 패키지" → **인트라넷으로 보내기** | `draft` (임시저장) |
| 2 | 인트라넷 | 기안자가 문서를 확인하고 **상신** | `submitted` |
| 3 | 인트라넷 | 결재선 순서대로 결재자가 **승인·협조 동의·반려** | `in_progress` → `approved` 또는 `rejected` |
| 4 | 서무비서 | 결재 패키지에 결과가 보임 (다음 할 일 안내) | 같은 상태 |

**서무비서는 스스로 상신하지 않습니다.** 상신은 사람이 인트라넷(또는 서무비서) 화면에서 직접 누릅니다. 지금 서무비서 코드의 원칙을 그대로 따릅니다.

### 3-2. API (모두 서무비서가 제공, 담당: 영운)

| 기능 | 방법·주소 | 지금 | 보내는 것 / 받는 것 |
|---|---|---|---|
| 인트라넷 화면 | `GET /intranet/` | **추가** | 레포의 `intranet/` 폴더를 그대로 보여 줌 |
| 결재함 목록 | `GET /api/approval/mock` | 있음 | `{"documents": [문서 요약, ...]}` 최신순 |
| 문서 하나 | `GET /api/approval/mock/{doc_no}` | 있음 | 3-3 문서 |
| 상신 | `POST /api/approval/mock/{doc_no}/submit` | **추가** | `{"user_id": "u01"}` → 바뀐 문서 |
| 결재 처리 | `POST /api/approval/mock/{doc_no}/actions` | **추가** | `{"user_id": "u03", "action": "approve", "comment": ""}` → 바뀐 문서 |
| 결재자 목록 | `GET /api/intranet/users` | **추가** | 4장 사용자 배열 |

- 오류는 HTTP 상태 코드와 `{"detail": "쉬운 한국어 설명"}` (서무비서 지금 방식)으로 돌려줍니다.
- 상신·결재 처리 결과는 같은 문서의 `package_id`로 서무비서 결재 패키지 상태에도 반영합니다.

### 3-3. 결재 문서 형식

서무비서가 지금 저장하는 항목(`doc_no`, `state`, `title`, `contents`, `drafter`, `approval_line`, `attachments`, `package_id`, `created`, `submitted`)에 아래를 더합니다.

```json
{
  "doc_no": "DEMO-20261105-0427",
  "state": "in_progress",
  "title": "물품 구매 품의 (노트북 2대)",
  "task": "구매·지출",
  "form_code": "F09",
  "contents": "본문(Markdown)",
  "drafter": "u01",
  "amount_won": 3000000,
  "approval_line": [
    {"order": 1, "type": "검토", "user_id": "u02", "label": "산울림청소년센터 부장", "result": "approve", "at": "2026-11-05T15:02:00", "comment": ""},
    {"order": 2, "type": "협조", "user_id": "u05", "label": "경영지원부 부장", "result": null, "at": null, "comment": ""},
    {"order": 3, "type": "전결", "user_id": "u03", "label": "산울림청소년센터 센터장", "result": null, "at": null, "comment": ""}
  ],
  "attachments": ["견적서_A.pdf"],
  "package_id": "P-0001",
  "created": "2026-11-05T14:30:00",
  "submitted": "2026-11-05T14:40:00"
}
```

- `type`은 기관설정서 4-1의 결재 용어 **검토, 협조, 결재, 전결, 대결** 중 하나입니다.
- 결재선은 `order` 순서대로 처리합니다 (하위 → 상위, 같은 직급은 소속 부서 → 타부서).
- 인트라넷은 `result`가 `null`인 첫 줄의 사람에게만 버튼을 보여 줍니다.

| `state` | 화면 표시 |
|---|---|
| `draft` | 임시저장 |
| `submitted` | 상신 |
| `in_progress` | 결재 중 |
| `approved` | 결재 완료 |
| `rejected` | 반려 |

| `action` | 뜻 |
|---|---|
| `approve` | 승인 (검토·결재·전결·대결) |
| `agree` / `disagree` | 협조 동의 / 부동의 (부동의는 `comment`에 사유 필수, 사무§20) |
| `reject` | 반려 (`comment`에 사유) |

코드 값은 영어, 화면 글자는 한국어입니다. 코드 값만 맞추면 화면 글자는 각자 바꿔도 됩니다.

### 3-4. 인트라넷 화면 쪽 약속 (담당: 준호)

- 전자결재 메뉴(결재함·상신문서)는 **`/api/approval/mock`에서 문서를 읽어** 보여 줍니다. 지금처럼 브라우저 저장소(localStorage)에만 두지 않습니다.
- 상신·승인·반려 버튼은 3-2의 `submit`·`actions`를 부릅니다. 누른 뒤 목록을 다시 읽어 상태를 갱신합니다.
- 화면 위쪽 "데모 사용자"에서 `GET /api/intranet/users` 목록 중 한 명을 고르면 그 사람 기준으로 결재함이 보입니다.
- 주소는 앞에 `http://localhost:8000`을 붙이지 말고 `/api/...`로 씁니다.
- `index.html`을 더블클릭해 따로 열었을 때(서무비서 없음)는 API 호출이 실패합니다. 그때는 화면 안의 견본 문서를 보여 주고 "서무비서와 연결되지 않음"을 작게 표시합니다.
- 인트라넷의 다른 메뉴(메일, 일정, 게시판 등)는 지금처럼 화면 안 데이터로 둬도 됩니다.

## 4. 시연 사용자와 결재선

- 기관명·조직·직위는 `data/00_기관설정서.md`를 그대로 따릅니다.
- 사람 이름은 넣지 않고 **소속 + 직위**로만 부릅니다 (기관설정서 9장, AGENTS.md 4장).
- 아래 목록은 영운이 서무비서에 넣고 `GET /api/intranet/users`로 내보냅니다. 서무비서의 담당자 선택 화면도 같은 목록을 씁니다.

| user_id | 소속 | 직위 | 역할 |
|---|---|---|---|
