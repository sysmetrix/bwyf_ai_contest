# 기존 작업 이관 요청문 (AI에 붙여 넣기용)

각자 따로 작업한 파일을 공용 레포로 옮길 때 씁니다. **터미널은 쓰지 않아도 됩니다.**

## 사용법

1. 쓰시는 AI 코딩 도구(Claude Code, Cursor 등)를 엽니다.
2. 아래 "요청문" 상자 안의 글을 **통째로 복사해서 붙여 넣습니다.**
3. AI가 묻는 것(이름, 기존 작업 폴더 위치)에만 답합니다.
4. 중간에 GitHub 로그인 창이 뜨면 직접 로그인합니다. (이것만은 AI가 대신할 수 없습니다)
5. AI가 "올라갈 파일 목록과 검사 결과"를 보여 주면 확인하고 "좋아"라고 답합니다.
6. 막히면 화면을 캡처해서 단톡방에 올려 주세요.

## 요청문

````markdown
너는 지금부터 나의 기존 작업 파일을 팀 공용 GitHub 레포로 안전하게 옮기는 일을 도와줘.
나는 터미널 명령어를 잘 모르니, 명령은 네가 직접 실행하고 나에게는 쉬운 말로 설명해 줘.

## 팀 레포 정보
- 레포: https://github.com/sysmetrix/bwyf_ai_contest (공개 레포. 누구나 볼 수 있음)
- 담당 폴더 (자기 폴더에만 파일을 넣는다)
  | 이름 | 맡은 일 | 내 폴더 | 브랜치 이름 |
  |---|---|---|---|
  | 이영운 | 서무비서 메인 프로그램 | app/ | youngwoon/기존작업이관 |
  | 김지은 | 규정·서식 정리본 | data/ | jieun/기존작업이관 |
  | 김준호 | 가상 인트라넷 | intranet/ | junho/기존작업이관 |

## 진행 순서 (단계마다 무엇을 했는지 한두 줄로 알려 줘)

0. 먼저 나에게 두 가지를 물어봐: ① 내 이름 ② 기존 작업 파일이 있는 폴더 위치.
   그리고 레포를 받을 위치를 제안하고 내 동의를 받아. (기존 작업 폴더 안은 안 됨)

1. 준비 확인: Git이 설치돼 있는지 확인해. 없으면 설치를 도와줘.

2. 레포 받기: 레포를 새 폴더에 clone 하고, 그 폴더에서 `git config core.hooksPath .githooks`를 실행해.
   그다음 레포의 AGENTS.md를 읽고, 지켜야 할 규칙을 나에게 다섯 줄 이내로 요약해 줘.

3. 브랜치 만들기: 위 표의 내 브랜치 이름으로 새 브랜치를 만들어. main에서는 절대 작업하지 마.

4. 파일 복사: 기존 작업 폴더의 파일을 레포의 "내 폴더" 안으로 **복사**해. (원본은 옮기거나 지우지 마)
   다음은 복사하지 마: .git 폴더, .env 같은 비밀정보 파일, node_modules, venv, __pycache__, 로그(.log), 개인 편집기 설정(.vscode, .idea)
   50MB가 넘는 파일이 있으면 복사하기 전에 나에게 물어봐.

5. 안전 검사 (가장 중요. 공개 레포라서 한 번 올라가면 지워도 기록이 남는다):
   복사한 파일 전체에서 아래 항목을 찾아서 표로 보여 줘. 파일 이름과 줄도 함께 알려 줘.
   - API 키, 토큰, 비밀번호 (예: sk-, ghp_, AKIA, password=, api_key=)
   - 실제 사람 이름, 전화·휴대폰 번호, 주소, 실제 이메일, 주민·계좌번호, 실제 문서번호, 업체·식당 상호
   - 원본 파일(규정집·매뉴얼 PDF, 한글 hwp·hwpx 원본, 스캔본), 실제 그룹웨어(gw.bwyf.or.kr) 주소
   (재단 이름·부천시 같은 지명과, 정리한 규정 내용은 써도 된다. 찾지 않아도 됨)
   찾은 것이 있으면 어떻게 고칠지(삭제, 직위나 ○○○로 바꾸기, 환경변수로 빼기) 제안하고, 내가 고르게 해 줘.

6. 범위 검사: git status로 바뀐 파일을 보여 주고, "내 폴더" 밖의 파일이 바뀌지 않았는지 확인해 줘.
   밖의 파일이 바뀌었으면 되돌리고, 꼭 필요한 파일이면 원하(@sysmetrix)에게 부탁할 내용을 정리해 줘.

7. 여기서 멈추고 나에게 확인받아: "올라갈 파일 목록 + 검사 결과"를 요약해서 보여 주고, 내가 "좋아"라고 하기 전에는 커밋하지 마.

8. 커밋과 PR: 내가 좋다고 하면
   - 커밋 메시지는 한국어로: `기존 작업 이관: (무엇을) 옮김`
   - 내 브랜치로 push 해. (GitHub 로그인 창이 뜨면 내가 로그인할게)
   - PR을 만들어. 본문은 레포의 .github/pull_request_template.md 양식을 채워.
     PR을 만드는 도구가 없으면, push 결과에 나오는 PR 만들기 주소를 나에게 알려 주고 웹에서 무엇을 누르면 되는지 안내해 줘.
   - 마지막으로 PR 주소를 알려 줘.

## 절대 하지 말 것
- main 브랜치에 커밋하거나 push 하기 (막혀 있으니 우회하지 말 것. --no-verify 금지)
- git push --force, git reset --hard, 브랜치 삭제
- 기존 작업 폴더의 원본 파일을 옮기거나 지우기
- 다른 사람 폴더(app/, data/, intranet/ 중 내 것이 아닌 곳) 수정하기
- 오류가 나면 스스로 우회하지 말고, 무슨 일이 생겼는지 쉬운 말로 설명하고 나에게 물어보기
````

## 리뷰어(원하)가 확인할 것

이관 PR이 올라오면 머지하기 전에 아래만 봅니다.

- 담당 폴더(`app/`, `data/`, `intranet/`) 밖의 파일이 바뀌지 않았나
- API 키·비밀번호·실명·연락처·문서번호·업체 상호·원본 파일(PDF·한글)이 없나. 있으면 머지하지 말고 고쳐 달라고 합니다. 이미 푸시된 키는 기록에 남으므로 새로 발급받아야 합니다.
- 첫 PR에 기존 작업을 옮기는 것 말고 다른 변경이 섞이지 않았나

각자 자기 폴더만 고쳤다면 세 PR은 서로 충돌하지 않으므로 순서와 상관없이 머지하면 됩니다.
